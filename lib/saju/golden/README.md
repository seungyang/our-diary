# 만세력 골든 데이터

`cases.json`의 생년월일시를 참고 사이트에 넣어 받은 결과가 `sites/*.json`에 있다. `npm run saju:test`가 엔진과 비교한다.

## 수집 현황 (2026-09-22, 크롬 디버그로 자동 수집)
- `fateup.json` 사주풀이도우미(kr.fateup.com) — 24/24. 기본값 "한국 서울(-30분)". **월주·일주 기준 사이트.**
- `timelupin.json` 타임루팡 — 24/24. 서울 -32분. 절기를 날짜 단위로만 보고(시각 무시) 서머타임을 안 빼서 월주·시주가 자주 어긋난다. 참고용.
- `forceteller.json` 포스텔러 — 24/24. 서울 -32분 + 서머타임 -60분. 연·월주 24/24 일치. **23시대는 다음 날 일주**(정자시 관례)라 c05·c10·c18의 일·시주가 엔진과 다르다. 대운수는 다른 방식(4/24)이라 비교하지 않는다.
- 운신 — 자동화 실패. 손으로 채우면 같은 형식으로 추가.
- `cases.json`의 `expected`는 문헌 예시(사주나루 블로그 1988-12-07 14:00 여 → 무진 갑자 병신 을미, 대운수 1).

## 엔진이 택한 관례
- 서머타임(1948~1960, 1987~1988) 자동 차감. 1954-03-21~1961-08-09는 표준시가 UTC+8:30이라 30분 보정을 겹쳐 하지 않는다(사이트들은 이 시기를 모른다 → c04 차이).
- 서울 경도 보정 30분(fateup과 같음). 타임루팡은 32분이라 정각 경계 케이스(c12, c16)에서 갈린다.
- 일주는 보정 후 자정에 바뀐다(사주풀이도우미·타임루팡과 같음). 포스텔러는 23시부터 다음 날로 본다 — 사용자가 "0~24시 기준"으로 정해 자정 방식을 택했다. 바꾸려면 `computeChart`에서 `localHour >= 23`일 때 `dayCount += 1`을 넣으면 된다.
- 23시대의 시간(時干): 그날 일간 기준(타임루팡 방식). fateup은 다음 날 일간 기준(야자시 방식) → c05·c10·c18 차이. 옵션으로 두지 않았다(사용자 결정: 0~24시 기준 하나).
- 대운수 = floor(ceil(일수)/3)+1. fateup과 19/24 일치. 나머지는 절기 시각 차이로 ±1.
